# Update Notes: 2026-06-24 11:50:00 UTC

## Permission UI & Logic Fixes
- **JSON Parsing Fix:** Removed `JSON.parse()` and unnecessary quotes around `tojson` template variables in `permissions.html` to fix the JavaScript syntax error. Checkboxes now properly reflect granted permissions upon selecting a user.
- **Removed Owner Bypasses:** 
  - `database.py`: Removed owner bypass logic (`s.owner_id = ?` and `sch.user_id = ?`) from `list_accessible_scripts`, `check_script_access`, and `list_schedules` to ensure the creator of a script/schedule must be explicitly granted permissions to run, edit, delete, enable, disable, and duplicate.
  - `web_routes.py`: Removed the `is_owner` check in `bulk_update_schedules` so the backend strictly enforces permissions.
  - `scheduler.html`: Removed `sch.user_id == current_user.id` checks from the Jinja template logic for Enable, Disable, Run, and Duplicate actions.

## Results
- File Explorer in worker detail page now strictly requires `can_run` and other explicit permissions; owners do not get automatic run/edit buttons unless granted.
- Scheduler page properly hides Enable/Disable, Run, and Duplicate buttons for schedules if the user hasn't been explicitly granted access, even if they created the schedule.
- Backend completely blocks any direct POST/GET requests to perform these actions if the user lacks explicit permissions.
